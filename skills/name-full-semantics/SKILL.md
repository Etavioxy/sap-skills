符号名（函数/变量/类型/文件名）的语义写全：

- **定位理解**：名字携带归属和位置，读者只看名字 + 所在作用域名，就能说出这是哪个任务的哪一环，理解作者设计意图。
- **关键词检索**：名字携带任务实际使用的术语，拿任务关键词 grep 就能搜到，而且全库没有重名。
- **使用威慑**：名字写明它属于哪条任务线，不在这条线上的人看到就知道不是给自己用的，不敢随手依赖，就算误用，review 时也一眼暴露。
- **防止迭代腐烂**：名字是符号对外的契约，行为漂移之后名字和行为对不上，这个错位本身就是 bug 信号。

不是所有符号都需要写全，写全最适合的情景：可观测性符号（计数、诊断、指标）、跨模块导出的符号、临时符号、过程性文件名。

## 原则：名字 = 归属 + 位置

- **归属**：属于哪个任务。用这条任务线实际使用的术语（机制名、数据对象名），不用零信息动作词——修复、优化、处理这类不携带任务信息的动词。
- **位置**：在这条线的哪一环。从下面语义类别里挑。

## 语义类别

- **阶段**：链上时机——前 / 后
- **对象**：作用于什么
- **方向**：读 / 写、生产 / 消费
- **粒度**：逐个 / 整批、单项 / 集合
- **范围**：全局 / 逐实例 / 逐帧
- **切面**：实际 / 全部、成功 / 尝试
- **线程**：主线程 / 工作线程、同步 / 异步
- **层次**：运行时 / 编辑期 / 诊断
- **生命周期**：临时 / 常驻
- **意图**：快路径 / 兜底
- **种类**（变量常用）：计数、区间、屏障、开关

## 组装

按需挑，不求全：这条符号区别于同任务兄弟符号的语义才进名字；作用域（类/文件/任务域）已表达的不重复；成对维度只让有标记侧占字，默认侧（运行时、全部这类无标记侧）沉默。

## 测试：两条过线即「全」

- 包含任务关键词，能被 grep 搜索到
- 只看名字 + 作用域名，能说出它坐哪一环

## 误区

把「写全」读成「写长」「按槽位全填」——机械堆出全维度长名，或照抄固定词表让跨项目命名千篇一律。写全由测试判定，不由长度、维度数、词表匹配度判定。
