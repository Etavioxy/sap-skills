# Plan Analysis Matrix

## 何时使用

- **硬触发关键词**：只要用户提到“方案对比 / 痛点 / 取舍 / 脑暴”，必须触发本 skill（先分析后实现）。
- 用户要“给多个方案”或“按多元参考维度比较”。
- 用户强调“抓核心痛点，不要维度泛滥”。
- 用户要求“附直观表格 + 明确推荐”。

## 核心原则

1. 先提炼 3-5 个核心痛点，再展开方案。
2. 至少给 3 个可比较方案；你可以从以下多元的角度思考：
    - 策略（激进/平稳）
    - 治理方式（自动化/人工确认）
    - 一致性（渐进实现/彻底重构）
    - 选型参考（新框架/旧技术）；给方案前必须用搜索工具查现有选型，方案基于真实选项，不凭空脑暴。
3. 每个方案必须写：思路、优势、风险、适用边界，并说明采用了哪些参考维度。
4. 对比维度固定 4-6 个，不做维度堆砌。
5. 最后给“主推方案 + 备选方案 + 落地节奏”。
6. 此为分析型输出，不给代码不做实现。

## 输出要求

### 基础格式

- 使用分点与分段结构，避免长段散文。
- 先提炼问题背景与目标（1-2 句）。
- 再列核心痛点（3-5 条，短句）。
- 再给多方案（每个方案写：思路、优点、风险、适用边界）。
- 最后给推荐与落地顺序（阶段化）。

### 表格规范

- 对比表默认维度为：`实施成本`、`痛点模板`、`特性模板`、`扩展性`（不含上线速度）。
- 列出多个痛点/特性的维度，使用具体名称替换模板（`<痛点1/2/3>`、`<特性1/2/3>`）。
- 强度使用 emoji 表示。
- 方案数量通常小于维度数。所以使用维度行、方案列。

emoji 语义维度（可扩展）：

- 对错：`✅ ⚠️ ❌`
- 人脸（好坏）：`😄 🙂 😐 🙁 😖`
- 颜色（强弱）：`🟢 🟡 🟠 🔴`
- 难易：`😌 😅 😰 😵 🤯`
- 数量：`📦 / 📦📦 / 📦📦📦...`
- 速度：`🐢 🚶 🏃 ⚡ 🚀`
- 紧急性：`🕊️ 📌 ⏳ 🔥 🚨`
- 完成度：`📝 🛠️ 🧪 ✅`

维度和级数都不固定，可按场景自由发挥。

### 对比表参考模板

按实际任务增减痛点/特性行，保持维度行、方案列。

| 维度 | 方案A | 方案B | 方案C |
|---|---|---|---|
| 实施成本 | 🤯 | 😵 | 😌 |
| 扩展性 | 🔌 | 🧩 | 🏗️ |
| <痛点1> | 🌩️ | ⛅ | ☀️ |
| <痛点2...> | 🔴 | 🟢 | 🟡 |
| <特性1> | ✅ | ⚠️ | ❌ |
| <特性2...> | 👎 | 👌 | 👍 |
| ... | ... | ... | ... |

## 约束处理

- 保持分点结构、语气和结论顺序稳定。
- 优先删除冗余解释，不删除核心痛点、差异、表格、推荐。
- 命中硬触发关键词时，不得跳过本 skill 直接给实现方案。
- **禁止复活已否决方案**：同一轮或同一任务的前序脑暴中已被用户明确否决的方案，后续轮次不得重新包装为选项。每一轮必须基于上一轮已确定的决策结论收窄方案空间，而非无限发散。

## 质量检查

- [ ] 是否先痛点后方案，且至少 3 个方案并体现多元参考维度
- [ ] 是否每档都写了优势、风险、适用边界
- [ ] 是否维度收敛到 4-6 个，并说明默认/扩展关系
- [ ] 是否使用转置表（维度行、方案列）
- [ ] 是否给了 emoji 映射且级数可扩展
- [ ] 是否输出主推方案、备选方案、迁移节奏
- [ ] 方案是否基于搜索到的真实选型（有名称/来源），而非凭空脑暴的形态
