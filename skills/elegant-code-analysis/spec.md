# spec — 演进流程

本 skill 是动态开放的：内容随实践持续补充。

- 新思想先进 drafts/（自由文本，一句或一段，附来源），不直接改 SKILL.md。
- 验证（用户确认或代码实证）后提升进 SKILL.md 的对应位置（评估手段 / 评估三问 / Consistency / Blast Radius 度量 / 权衡模板）。
- 模板不追求一行，写清楚判断即可。
- SKILL.md 不含任何"开放/演进"元话，只留调用 agent 用的内容；演进机制与草稿都在 Notes 侧。
- 结构原则：整体骨架错落有致、详略得当——Consistency 与 Blast Radius 是教程节（展开），权衡模板是一段判断（收紧），评估手段/三问是引导。
- 层级原则：评估手段（怎么评估：按层逐个深入，把足迹想全）与评估三问（评估什么）分离；跨层差异属于 Blast Radius 的度量维度，不属于 Consistency（一致性管同层内同构，层级差异管跨层不同构）。
- 分层不应该是「代码」：分层是通用心法，对象是「任意被分析对象」（代码架构 / 检查验证过程 / 数据流 / 决策流程……），「对代码分层」只是其中一个实例。具体实例（如编译检查分几层）是具体能力，落 drafts，不进 SKILL.md。
- 规范 skill 使用：SKILL.md 记心法（通用能力），drafts 记具体能力（某对象具体分几层），spec 记本规范；心法进 SKILL.md、具体实例进 drafts 的边界不混。

## 四个并列功能

skill 是四个**并列的独立功能**，各自可单独触发、不强制串行：

1. **分层理解 + 不同层解法可能** —— 对任意被分析对象分层，枚举每层的解法候选。
2. **重构方案 blast radius 对比** —— 每个候选单独评估影响面，横向对比。
3. **代码结构优雅性诊断（review）** —— 诊断现有代码哪里不优雅、不一致。
4. **洞察点归纳进已有文档/设计** —— 把分析得到的洞察落进既有文档/设计，补成新原则。

性质分三类：1/2 是「改前评估」，3 是「诊断现状」，4 是「沉淀洞察」。

- 可观测性（测试友好性）：纳入心法，是评估优雅性的一个维度，不单列成功能。
