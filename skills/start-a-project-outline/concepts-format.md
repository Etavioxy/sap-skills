# concepts.md 格式规范

`concepts.md` 是领域概念的**唯一术语源**（SAP concepts 阶段产物）。

职责边界：`concepts.md` 回答「是什么、边界在哪」；`docs/` 回答「怎么实现、接口长什么样」。

## 概念条目格式

每个概念一个条目，包含：

- **标题**——中英文术语并列：英文 + 中文，如 `Concept（概念）`。
- **编号**——`1.` / `1a.`（子概念）等，供 ideas / spec / docs / 各文档引用，不重复定义。
- **定位**——概念是什么，一句话讲清。描述真实实现形态，消除歧义和不确定的解读，暴露设计模式。
- **边界与关系**——在正文中直接陈述：与相关概念的界限、被谁使用、在整体中的位置。不用独立小节，揉进概念描述。每条概念都要尝试挖出与直接概念的联系（驱动 / 读写 / 被消费 / 对偶）。
- **一对多、多对多关系推荐写明两端**——凡是数量不是一的联系，把「一」在哪端、「多」在哪端、写出来是什么形态（组合 / 分发 / 分组隔离 / 矩阵），只写单数形态算没说完。
- **只写「直接联系」**——只写直接关系，不写多余间接关系。不重述关系概念的定义、机制或背景事实；关系以短、清晰为准。
- **关系句的主语必须是本概念**——只写「本概念与关系概念怎么连」，不写主语是邻居的句子，归邻居条目。

实现细节、协议、config 字段、命令集归对应 `docs/`，不在概念条目里展开。

## 例子

每个例子用一段叙述分析一条完整过程，概念标注揉进叙述（加粗概念名），例子中不用表格。用覆盖矩阵核验每个概念都被覆盖。

## 覆盖矩阵

`concepts.md` 含概念间关系覆盖矩阵（SAP 定义）。常见形式是**概念 × 例子矩阵表**：

```
| 概念 \ 例 | 例 A | 例 B | 例 C |
|------|:---:|:---:|:---:|
| C1 ... | ✅ |   | ✅ |
```

约束：每个概念至少被一例覆盖；一例至少覆盖三个概念；例数与概念数不对等。
