# docs/ 文档格式规范

`docs/` 存放实现层的文档——概念、流程、路线图、工具说明等。

职责边界：概念「是什么、边界在哪」→ `concepts.md`；实现细节 / 接口 / 流程 / 路线图 → `docs/`。

通用原则：

- 技术细节的两类内容——「怎么运作 / 有哪些规则」与「类型 / 契约 / schema / 接口」——都要给出可照抄的形态：声明怎么写、标识符与键名怎么拼、输入输出什么格式，使用条件细化到需求性质、分类选择、决策原因，语法结构细化到挂点、属性 / tag 字面形态、枚举取值、字段名与缩进形态。
- 不写版本信息、状态标注、调研论证过程、单次会话回顾、待落地清单、实现前校准项 + 回填约定、业务代码实现：控制流具体代码 / 具体语句不写，用最简单的方式概括描述逻辑（ASCII 图、接口、状态机）。

## 文件命名

`docs/<slug>.md`——小写连字符，命名反映内容主题。

## 原则段

文档顶部用 `- **<标签>**：<内容>` 列表逐条列出该模块的设计哲学，包含「本文档范围」等条目。

## 内容组织

结构不强制统一——按内容特征组织（实现 / 接口 / 数据流等）。要点：

- 只写该文档自己的内容，不重复其他文档已定义的（用引用代替复制）。
- 实现变了就同步更新，保持文档 = 当前契约。
