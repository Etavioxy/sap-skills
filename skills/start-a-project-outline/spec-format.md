# spec.md 格式规范

`spec.md` 是项目的技术规格（SAP spec1 → spec2 阶段产物，随 src 持续修订，不是一次定稿）。

职责边界：技术选型 / 架构决策 → `spec.md`；概念级推导 / 实现原则 → `docs/`；不在 `spec.md` 展开某概念的实现细节。

通用原则：不写版本号或版本归属；不写易变的状态标注（当前契约 / 待落地 / 未决），被取代的历史方案删除或在原文标注历史。

## 必有的部分

真实项目的 spec.md 结构各不相同，但有两个共同点：

1. **技术选型**——选什么技术栈，为什么。表格或列表：选型 / 理由。
2. **技术决策 / 架构决定**——关键实现决策及其理由。

## 可有的部分（按项目需要）

各项目差异很大，不强制统一：

- **初步 insight**——每条：认识 + 真实数据 + 设计后果。
- **模块结构 + 目录布局**——ASCII 树。
- **阶段计划** / **验收基线**——推进计划或可核验的验收目标。
- **排除 / 遗留决策 / 风险与未决**——不选方案、遗留问题、未决风险。
