# scenario 格式规范

**scenario（剧本）** 是端到端验证的写法：**写「用户会怎么用」，不写命令序列**——脚本跑命令，剧本跑人。用在 experiments 的命题验证与实施阶段的 e2e。

## 位置与命名

`<仓>/plans/<plan 同名>-scenarios/DD-<kebab-case>.md`：一剧本一文件；目录跟 plan 同名 + `-scenarios`，`DD` 两位序号，文件名用 kebab-case 描述这一幕。

## 七段

| 段 | 写什么 |
|---|---|
| 用户会怎么用 | 一段叙述：他是谁、做什么、期待什么。**不写命令**。 |
| 前置 | 这一幕开始前必须成立的状态：环境 · 数据 · 谁在场 |
| 执行时要 invoke 的 skill | 执行者照它 invoke（`[[skill]]` + 「请 invoke」）；纪律真源在 skill 自己那儿，不复述正文 |
| 步骤（人类动作） | 编号的人的动作，一步一个动作 |
| 预期（PASS 判据） | 可观测判据，绑在契约 / 文档口径上——不写「命令跑通了」 |
| timeout（最小起步） | 每步一个起步值；**超时必须最小且尽快触发**，禁止 sleep 式等待 |
| 卡点记录 | 跑的时候填 |

## 依赖面：真环境 / 替身

**替身只替一环，其余全程真跑**，并在剧本里写明替掉的是哪一环（例：替「数据从哪来」）。不写清就等于降级，不算一遍过。

## 执行纪律

- **先 review 剧本**，再执行。
- 执行用**独立上下文**——要发现的正是主 agent 自己的观测与调用盲区。
- **卡点三条**：无法观测 / 无法调用 / 调用超时；**任何超时都不算一遍过**，记为卡点。
- 跑完把**实测 timeout 回写**进剧本。
- 等待循环必须绑终止条件并设有限次数。
